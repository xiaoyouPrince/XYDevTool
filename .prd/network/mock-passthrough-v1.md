# Mock 透传与留存 — PRD v1

> **状态**：P0 / P1 / P2 已实现  
> **模块**：Network / Mock Passthrough  
> **最后更新**：2026-11-17  
> **决策**：未命中自动透传留存（1A）；写入请求历史（2A）

---

## 1. 目标

客户端将 host 指向 Mock 后：可按路由走 **缓存** 或 **透传真实上游**；透传响应写入历史，下次可缓存回放，减少手工录入。

## 2. 已定决策

| 项 | 结论 |
|----|------|
| 未命中 | 已配上游且开启透传 → 自动透传并留存；否则 404 |
| 留存 | 写入请求历史（自动进 Mock 路由表） |
| 直播鉴权 | 原样转发客户端 Header/Body |
| 新捕获默认 | 路由模式 `cache` |
| Token/脚本 | P2：响应抽变量 + 出站 Header 模板 |

## 3. 分期

| 阶段 | 内容 |
|------|------|
| **P0** | 完整请求解析、上游 URLSession、miss 透传、upsert 历史、全局开关与上游 URL、日志 |
| **P1** | 路由级 `cache` / `passthrough`、写回历史开关、非 2xx 仍可留存 |
| **P2** | JSON 路径 → 变量；出站 Header 变量替换 |

## 4. 验收（P0）

1. 配置真实上游，客户端打未知 path → 真响应返回且历史出现条目，再次请求可缓存命中  
2. 关闭透传 → miss 仍 404  
3. 已有缓存路由行为不变  
4. 关主窗停 Mock
