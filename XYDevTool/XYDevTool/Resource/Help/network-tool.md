# 网络请求工具

轻量、纯本地的 HTTP 调试工具，适合日常接口联调。历史、变量、脚本保存在本机，可整套导出/导入（发请求本身仍需要能访问目标接口）。

## 界面布局

- **左侧**：请求历史树（分组 / 请求）
- **上方**：名称、URL、方法、🔒 锁定、Submit
- **中部**：请求头 / 请求参数（JSON）
- **下方**：响应展示区
- **底部状态栏**：状态文案；**文档** / **Mock** / ⚙️ **设置**均打开独立可缩放窗口

## 发请求

1. 填写 **请求名称**、**URL**，选择 **GET / POST / PUT**
2. 在请求头 / 请求参数区输入 **JSON 对象**（均可留空，视为 `{}`）
3. 点击 **Submit** 发送

| 规则 | 说明 |
|------|------|
| 名称留空 | 自动使用 URL 的 host |
| 同名请求 | 按 **全局请求名** 覆盖已有记录（跨分组也会覆盖） |
| 异名请求 | **新建** 一条历史 |
| 选中分组 | 新建请求落入该分组；否则在根级 |
| GET 的「请求参数」 | 拼到 URL **query** |
| POST / PUT 的「请求参数」 | 作为 JSON **body**；未自带时会补 `Content-Type: application/json` |
| 非法 JSON | 弹窗拦截，不会发出 |
| 超时 | 默认约 20 秒 |

不支持 DELETE / PATCH 等方法。

## 历史记录（树形）

- 左侧树形展示，支持 **多层分组**、展开/折叠
- 点击 **请求** → 加载到编辑区；点击 **分组** → 选中，用于在其下新建
- 顶栏 **+**：选中分组时在其下新建分组，否则根级新建
- **整行拖拽**：同层排序、拖入/拖出分组（点删除按钮不会触发拖拽）
- **分组**：双击或右键重命名（右键菜单仅分组有）；分组名全树唯一；空组显示为 `名称 (empty)`
- **请求**：不能在树内直接改名，改顶栏 Name 后 Submit；行尾删除

### 锁定

- 开关在 **顶栏 Name 旁的 🔒 Toggle**（历史行本身不显示锁图标）
- **默认锁定**，防止误删
- 删除锁定请求前须先在顶栏解锁
- 删除分组「及内容」时，若含锁定请求，会再确认是否 **强制删除**

## 变量

在 URL / Header / Body 中使用 `{{key}}`，发请求前自动替换。

1. 底部 ⚙️ → **变量设置** → 新增 key/value
2. 支持嵌套；设置页可预览最终解析结果
3. 历史里 URL / Header / Body 存 **未替换** 的原文
4. 空 key、重复 key、循环引用会导致发请求失败

## 设置与脚本绑定

1. 打开底部状态栏 **⚙️ 设置**（独立窗口）
2. 先在库中新增全局前置 / 后置脚本
3. **必须先在左侧选中一条历史请求**，才能绑定：
   - **当前接口前置脚本**：单选
   - **当前接口后置脚本**：可多选
4. 未选中请求时，设置页无法完成按接口绑定

## 前置脚本（请求前）

用于签名、改 Header/Body 等，再交给 App 发包。

### 配置

1. 设置 → **全局前置脚本库** → 新增脚本
2. 命令示例：`swift ~/swift-pre-script.swift`（直接写 shell 或外部路径均可）
3. 选中历史请求 → **当前接口前置脚本**（单选）

### 传参方式

App 通过环境变量 **`XYDEV_PRE_REQUEST_JSON`** 注入请求 JSON，内容包括：

- `url` / `method`
- `headersText` / `parametersText`（可为空，视为 `{}`）
- `headers` / `parameters`（解析后的对象，作备用）

### 输出（stdout 一行 JSON）

| 模式 | 输出 | 行为 |
|------|------|------|
| 改包继续发 | `parametersText` + 可选 `headersText`、`url` | App **原样**写入 httpBody，保 key 顺序 |
| GET 已签名 | 完整 `url`（含 query） | 不再从字典拼 query |
| 脚本代发 | `{"response":"..."}` | 跳过 HTTP，直接展示 |
| 失败 | `{"error":"..."}` 或 stderr | 弹窗提示 |

### 签名注意

- POST / PUT 请用 **`parametersText`** 返回签名后的 JSON 字符串
- 不要只返回 `parameters` 对象，否则可能经 Dictionary 重序列化导致顺序变化、验签失败

## 后置脚本（响应后）

1. 设置 → **全局后置脚本库** → 新增脚本
2. 命令支持 `$1` / `$2`：`$1`=响应文本，`$2`=变量 JSON
3. 选中请求 → **当前接口后置脚本**（可多选）
4. 输出 JSON `{"variables":{...}}` 或多行 `key=value` 写回变量

## 响应区

- **没有**独立的「状态码 / Headers」面板
- 成功时展示的是合成后的 JSON 文本，常见字段：
  - `_statusCode`：HTTP 状态码
  - `_headers`：响应头
  - `_mimeType`：MIME
  - 若 body 是对象会合并进同一 JSON；数组 / 纯文本 / 二进制会分别放在 `_jsonArray` / `_text` / `_base64`
- 失败时多半只更新 **底部状态文案**，响应区不一定有新内容
- 写入历史的 response 也是这份合成展示串，不是原始字节流

## 导入 / 导出

所有导出都会在所选 **父目录** 下自建时间戳包：

```text
XYDevTool-Network-YYYYMMDD-HHmmss/
  manifest.json
  config/     # 历史、变量、前后置脚本
  mock/       # Mock 资产 JSON
  docs/       # 接口文档 Markdown
```

| 入口 | 操作 |
|------|------|
| ⚙️ 设置 → **导出全部** | 写入 config + mock + docs |
| ⚙️ 设置 → **仅导出配置** | 只写 config |
| ⚙️ 设置 → **导入…** | 选导出包根目录；有 mock 则一并导入。亦兼容旧版「四文件扁平目录」 |
| Mock → 资产 → 导出 | 只写 mock/ |
| Mock → 资产 → 导入 | 可选导出包目录或旧版单文件 `network_mock_assets.json` |
| 文档窗 → 导出 | 只写 docs/（复制剪贴板仍可用） |

说明：导入时 **docs 不回写**（仅归档）；config 为整包替换；前置脚本文件缺失则清空前置库。

## 接口文档

根据历史中的 JSON 样本，自动推断字段类型并生成 Markdown 说明。

1. 底部状态栏点 **文档**，会打开独立可缩放窗口（可与主窗并排）
2. 可选「仅当前选中分组」（需先在左侧选中分组）
3. 默认 **文档预览** 为渲染后的折叠章节；可切换 **Markdown 源码**
4. **复制** 为剪贴板源码；**导出** 写入统一导出包的 `docs/api-docs.md`

说明：每个接口按「标题 / uri / HTTP-Method / 请求参数 / 响应」输出，JSON 行内自动标注类型；同质数组默认展开前 2 项。请求参数、响应等较长小节用 GitHub 同款 `<details>` 折叠（预览可点开，导出 md 在 GitHub 亦可折叠）。枚举表与错误码留占位。响应会先剥离 `_statusCode` 等调试字段。

## Mock 服务（本地回放 / 透传）

把历史里已有响应的接口，变成局域网可访问的 HTTP Mock；也可透传到真实上游并自动录制。

1. 底部状态栏点 **Mock** 打开独立可缩放窗口
2. 确认端口（默认 `18080`）与局域网 IP → **启动**
3. 设备访问 `http://<IP>:<port>/<path>`，按 **Method + Path** 匹配历史（忽略 host / query）
4. 命中且模式为 **缓存**：返回历史/资产响应（自动去掉 `_statusCode` 等调试字段）
5. **透传**：开启「透传」并填写上游 Base URL（如 `https://api.example.com`）
   - 未命中路由 → 转发上游 → 写回「透传捕获」历史
   - **命中策略**（无需改手机 host）：**全部缓存** / **全部透传** 一键切换；状态栏会显示当前策略
   - 路由行仍可逐条覆盖；「清除逐条覆盖」后全部跟随全局策略
   - 高级：写回开关、非 2xx 留存、出站 Header 模板 `{{变量}}`、响应 JSON 抽变量
6. 未开透传时未匹配仍返回 `404` JSON
7. 关闭网络窗口或点 **停止** 会关闭服务

### 路由操作

- 左侧勾选可 **启用 / 禁用** 单条路由
- **右键** 路由：复制路径、复制完整 URL、复制 curl（含正确 Method，便于测 POST）
- 同 Method+Path 多条历史会标 **冲突**：点「冲突」或菜单「选择冲突来源」指定当前生效项（默认取历史树中最后一条）
- **自定义返回**：为该路由设置 Mock 专用 status/body（不改网络历史）；可随时清除

### 联调选项（P2）

- **匹配 Query**：关闭时只按 Method+Path；开启后还需 query 一致（参数名/值会排序后再比）
- **仅本机**：只监听 `127.0.0.1`，局域网不可访问（切换时若服务在跑会自动重启）
- **CORS**：是否返回 `Access-Control-Allow-Origin: *`（浏览器跨域调试用）
- **延迟**：响应前额外等待 N 毫秒（模拟慢网，上限 30000）

### Mock 资产（P3）

- 面板顶部 **资产…**：独立于网络历史的 Mock 目录，可新建 / 编辑 / 删除
- **从当前路由生成**、路由右键 **保存为资产**
- **导出 / 导入**：导出为统一包 `mock/`；导入支持导出包或旧版单文件；导入支持替换或合并
- 命中时 **资产优先于历史回放**；不改网络历史数据

说明：调试用途；未开「仅本机」时会向局域网暴露历史响应。不执行前置/后置脚本。浏览器地址栏只能发 GET，测 POST 请用「复制 curl」或控制台 `fetch`。

## 方法范围

- 支持 GET / POST / PUT
- POST、PUT 默认 JSON body；GET 的参数走 query
